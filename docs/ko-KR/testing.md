# 실통화 시험 절차

**언어** · [English](../en/testing.md) · 한국어 · [日本語](../ja-JP/testing.md) · [← README](README.md)

speexdsp AEC 중계(`speexrelay`)를 실제 통화에 물리는 방법.

## 순서를 지켜야 한다

**릴레이를 먼저 켜고, 그다음 통화한다.** 반대로 하면 상대 목소리가 아예 안 들린다.
BlackHole은 통로일 뿐이고, 거기 들어온 소리를 실제 스피커로 넘겨주는 것이 릴레이다.
릴레이가 없으면 소리가 BlackHole에 들어갔다 사라진다.

## 1. 릴레이 실행

```bash
cd mac-aec-relay
./speexrelay --mode aec --autocal
```

- `--duration`을 주지 않으면 Ctrl-C까지 계속 돈다
- 이 터미널은 통화 내내 열어둔다. 닫거나 Ctrl-C를 누르면 그 순간 상대 목소리가 끊긴다

## 2. FaceTime에서 장치 지정

FaceTime 비디오 메뉴에서:

- **마이크 = BlackHole 2ch**
- **출력 = BlackHole 16ch**

전화 앱은 자체 장치 메뉴가 없고 FaceTime 설정을 따라간다. 여기서 지정하면 전화 앱 통화도 같이 적용된다.

**주의:** 선택지가 하나뿐일 때 뜨는 체크 표시는 자동 선택 결과이지 명시 지정이 아니다. 항목을 직접 클릭해야 고정된다.

## 3. 통화 후 복구

릴레이를 Ctrl-C로 끄고, FaceTime 마이크와 출력을 **실제 마이크와 스피커**로 되돌린다.

BlackHole로 둔 채 릴레이를 끄면 다음 통화가 안 된다.

## 통화 중 로그에서 볼 것

```
[ 30s] mic -42.9/-60.7  ref -29.9/-50.3  out -43.4/-61.8  aecFrames=2929 refZero=2917
       ring mic=32 ref=4800(100ms drop=1200) refSpk=4288(89ms drop=5440) out=1024
```

| 항목 | 정상 | 이상하면 |
| --- | --- | --- |
| `ref` | 상대가 말할 때 −20 ~ −40 dB | −999가 계속되면 전화앱 출력이 BH16으로 안 감 |
| `refZero` | `aecFrames` 대비 낮을수록 좋다 | 절반 넘으면 참조가 자주 끊긴다는 뜻 |
| `ref=N(Xms ...)` | 100ms 근처 고정 | 계속 늘어나면 지연 누적 |
| `refSpk=N(Xms ...)` | 89~100ms 고정 | 늘어나면 상대 목소리가 점점 느려진다 |
| `mic` 대비 `out` | out이 더 낮아야 한다 | 같으면 AEC 미동작 |
| `underrun spk=` | 0 유지 | 늘면 소리가 끊긴다 |

시작할 때 이 줄이 나온다.

```
정합 캘리브레이션: 신호 대기 중 (통화가 시작되면 자동 보정)
```

상대가 말하기 시작하면 자동으로 보정되고 아래처럼 찍힌다.

```
정합 캘리브레이션: lag=5542 samples (115.5 ms) corr=0.395 (12s 후)
refdelay 적용: 5542 samples (115.5 ms) — AEC 상태 리셋
```

**이 두 줄이 안 나오면 AEC가 지연 보정 없이 도는 것이다.** 그 상태로는 에코가 거의 안 지워진다.

## 지금까지 고친 것 (2026-09-12)

| 문제 | 증상 | 조치 |
| --- | --- | --- |
| 렌더 게인 −18 dB | 상대 목소리가 작게 들림 | BH16의 무음 14채널까지 평균에 넣던 것을 활성 채널만 평균하도록 수정 |
| refSpk 지연 누적 | 목소리가 점점 느려짐 (352 → 651ms) | 백로그 상한 100ms 추가 |
| ref 단독 폭주 | 참조가 마이크보다 320ms 늦게 AEC에 도착 | mic와 무관하게 ref 자체 백로그 상한 적용 |
| autocal 실통화 실패 | "레벨 부족"으로 지연 보정 안 됨 | 신호가 올 때까지 최대 90초 대기, 백그라운드 스레드로 전환 |

## 현재 성능 (측정 모드, DDC 0.0625)

| 조건 | mic | out | 억제량 |
| --- | --- | --- | --- |
| bypass | −45.6 | −45.6 | 0.0 |
| autocal | −46.0 | −53.8 | 7.8 |
| autocal | −46.0 | −53.4 | 7.4 |
| autocal | −28.3 | −37.7 | 9.4 |
| autocal | −46.5 | −52.1 | 5.6 |

**측정 모드 억제량 5.6 ~ 9.4 dB.** bypass가 4회 모두 정확히 0이므로 무음 오판이 아니다.

다만 **측정 모드와 실통화는 조건이 다르다.** 측정은 테스트 음성이 즉시 재생되지만
실통화는 시작 시점에 참조가 없다. 실통화 성능은 위 표로 예측할 수 없고 직접 걸어봐야 안다.

**측정 기준을 섞지 않도록 주의한다.** 여기 억제량은 마이크 대비 출력이다. 참조
대비 출력으로 재면 공기 경로의 감쇠까지 들어가 같은 성능에도 훨씬 큰 값이 나오고,
두 값은 비교할 수 없다. 이것을 한 번 혼동해 "측정 47 dB 대 실통화 8-14 dB"라는
엉뚱한 격차가 만들어졌고 세 번의 수정이 헛돌았다.
