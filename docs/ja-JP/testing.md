# 実通話での試験手順

**言語** · [English](../en/testing.md) · [한국어](../ko-KR/testing.md) · 日本語 · [← README](README.md)

speexdsp の中継(`speexrelay`)を実際の通話に挟む方法です。

## 順序を守ること

**中継を先に起動し、それから通話します。** 逆にすると相手の声が全く聞こえません。
BlackHole は通り道でしかなく、そこに入った音を実際のスピーカーへ渡すのが中継です。
中継がないと音は BlackHole に入ったまま消えます。

launchd エージェントを入れてある場合(`./install.sh`)はすでに動いているので、
起動する必要はありません。

## 1. 中継を起動する

```bash
cd mac-aec-relay
./speexrelay --mode aec --autocal
```

- `--duration` を渡さなければ Ctrl-C まで動き続けます
- このターミナルは通話の間ずっと開けておきます。閉じたり Ctrl-C を押すと、その
  瞬間に相手の声が途切れます

## 2. FaceTime でデバイスを指定する

FaceTime のビデオメニューで:

- **マイク = BlackHole 2ch**
- **出力 = BlackHole 16ch**

電話アプリには独自のデバイスメニューがなく FaceTime の設定に従うので、ここで
指定すれば電話アプリの通話にも適用されます。

**注意:** 選択肢が一つしかないときに表示されるチェックは自動選択の結果であって、
明示的な指定ではありません。項目を直接クリックして固定します。

## 3. 通話後に戻す

手動で動かしている場合は Ctrl-C で中継を止め、FaceTime のマイクと出力を**実際の
マイクとスピーカー**に戻します。

BlackHole のまま中継を止めると次の通話ができません。

## 通話中にログで見るもの

```
[ 30s] mic -42.9/-60.7  ref -29.9/-50.3  out -43.4/-61.8  aecFrames=2929 refZero=2917
       ring mic=32 ref=4800(100ms drop=1200) refSpk=4288(89ms drop=5440) out=1024
```

| 項目 | 正常 | おかしいとき |
|---|---|---|
| `ref` | 相手が話すとき -20 〜 -40 dB | -999 が続くなら通話アプリの出力が BH16 へ行っていない |
| `refZero` | `aecFrames` に対して低いほど良い | 半分を超えると参照が頻繁に途切れている |
| `ref=N(Xms)` | 100 ms 付近で安定 | 増え続けるなら遅延が蓄積している |
| `refSpk=N(Xms)` | 89〜100 ms で安定 | 増えると相手の声が次第に遅れる |
| `mic` に対する `out` | `out` のほうが低いこと | 同じなら AEC が働いていない |
| `underrun spk=` | 0 を維持 | 増えると音が途切れる |

起動時にこの行が出ます。

```
정합 캘리브레이션: 신호 대기 중 (통화가 시작되면 자동 보정)
```

相手が話し始めると自動で補正され、こう出ます。

```
정합 캘리브레이션: lag=5542 samples (115.5 ms) corr=0.395 (12s 후)
refdelay 적용: 5542 samples (115.5 ms) — AEC 상태 리셋
```

**この二行が出なければ AEC は遅延補正なしで回っています。** その状態ではエコーは
ほとんど消えません。

## これまでに直したこと (2026-09-12)

| 問題 | 症状 | 対処 |
|---|---|---|
| レンダーゲイン -18 dB | 相手の声が小さい | BH16 の無音 14 チャンネルまで平均に入れていたのを、有効チャンネルだけの平均に修正 |
| refSpk の遅延蓄積 | 声が次第に遅れる(352 → 651 ms) | バックログ上限 100 ms を追加 |
| 参照単独の暴走 | 参照がマイクより 320 ms 遅れて AEC に届く | mic と無関係に参照自体のバックログ上限を適用 |
| autocal が実通話で失敗 | 「レベル不足」で遅延補正されない | 信号が来るまで最大 90 秒待機、バックグラウンドスレッドへ移行 |

## ベンチでの結果

| 条件 | mic | out | 抑圧量 |
|---|---|---|---|
| bypass | −45.6 | −45.6 | 0.0 |
| autocal | −46.0 | −53.8 | 7.8 |
| autocal | −46.0 | −53.4 | 7.4 |
| autocal | −28.3 | −37.7 | 9.4 |
| autocal | −46.5 | −52.1 | 5.6 |

**ベンチでの抑圧量は 5.6 〜 9.4 dB。** bypass が 4 回ともきっちり 0 なので、無音を
成功と誤判定したものではありません。

ただし **ベンチと実通話は条件が異なります。** ベンチはテスト音声が即座に鳴ります
が、実通話は開始時点で参照がありません。実通話の性能はこの表からは予測できず、
実際にかけてみるしかありません。

**測定基準を混ぜないよう注意してください。** ここでの抑圧量はマイク対出力です。
参照対出力で測ると空気経路の減衰まで入り、同じ性能でもはるかに大きな値が出るので、
二つは比較できません。これを一度混同して「ベンチ 47 dB 対 実通話 8-14 dB」という
誤った差が生まれ、三度の修正が空回りしました。
